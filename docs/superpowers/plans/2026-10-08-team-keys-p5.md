# Team Keys Phase 5 (Personal Keys and Recovery Code) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Personal notebooks get random container keys wrapped to the user's own identity, so the server can no longer read them and a password change no longer orphans them. A one-time recovery code, generated and shown in the browser, wraps a server-held copy of the identity so a new browser can get it back without any trusted device.

**Architecture:** P5 adds one rule, "the login key never seals anything new". `writeKey` stops returning the login-derived key, so every write needs a container key. A notebook's first key is minted with the existing rotation route by its owner's browser, at creation or on the first open after the upgrade. The existing P4 review-and-close machinery then migrates personal notebooks exactly as it migrates team notebooks. Rows written before the key are labelled "not end-to-end verified" and re-sealed only when ticked. Edits waiting for a key are sealed with a key derived from the identity instead of the password, which resolves N3. On the server, migration `0025` adds a recovery-code copy beside the identity, and three routes set it (compare-and-swap), fetch it (step-up, audited, rate-limited) and reset the identity (step-up, lose-everything, explicit). Administrator resets and account recovery stop deleting the identity: they remove only the password-wrapped copy.

**Tech Stack:** Go 1.26 (`net/http`, SQLite via `modernc`, stdlib `crypto/pbkdf2`), TypeScript/React (Vite, vitest, fake-indexeddb, `@noble/ciphers`/`@noble/curves` 2.4.0 already pinned), `@playwright/test` 1.63.0. No new dependencies.

## Resolved ambiguities (recorded in the spec in Task 10)

### 1. The login key never seals anything new, for every notebook
"New personal containers never use the login key" cannot be enforced by reading `kind`, because `kind` is a server claim. The only rule that reads no server claim is the uniform one: `writeKey` returns no key while a notebook has never been shared. The login key keeps reading legacy rows until each device closes them (P4). Everything new is sealed with a container key the server never sees. This also closes F1 for unshared team notebooks, which until now received new writes under keys the server can derive.

### 2. Personal notebooks are migrated by the P4 review, not a background pass
Spec §4 point 5 planned a background pass on login, because "the owner is the only author". P4 ruling 3 already rejected background passes: the login key is derivable by the server, so a personal row it forged would be laundered into verified content. The owner's browser therefore mints a personal notebook's key on the first open after the upgrade. P4 then does the rest unchanged: the banner, the review dialog with nothing pre-ticked, the approval that carries the reviewed copy, re-seal, and closure. P5 changes only the copy (Task 9), so the same text reads correctly for personal and team notebooks.

### 3. A team never waits for identity-less members any more
Rule 1 makes a never-shared notebook read-only for everyone. Keeping P3a's `blocked` plan, which held back the first key while a member had no identity, would lock the whole team instead of one member. So the first key is minted for the members who have identities. Members without one see "no encryption key yet" in the member list (P3b) and are wrapped by the sweep once they create one. The `blocked` plan and its notice are deleted.

### 4. A first key waits for a recoverable identity
An SSO account's identity is device-only until it saves a recovery code. Before P5 its personal notebooks were keyed by the master password and survived losing every browser. Minting under a device-only identity with no copy would turn "lost browser" into "lost notebooks". So `planSweep` refuses a first mint until a password copy or a recovery-code copy exists (`unrecoverable`), and the notebook says so. Re-mints after a removal are never held: the content already depends on the identity. Password accounts with their P1 password copy are recoverable from the start.

### 5. Edits waiting for a key are sealed with the identity, not the password (N3)
`waitingKey` is HKDF over the identity private key with its own label, so it is separated from every other use of that key. A waiting edit therefore survives:
- a password change in any browser;
- "Forget this device", once the identity comes back by linking, the recovery code or the password.

Entries sealed with the login key before P5, or by a browser that held no identity, still open with the login key. `resealWaitingEdits` stays for those. Local entries are this browser's own writes, so trying two keys there is not the server-row trial decryption P3a ruling 1 forbids.

### 6. A password change warns only while login-key items remain
After P5 a password change orphans only legacy rows that no device has re-sealed. The form counts notebooks that are never-shared or still open on this browser (`legacyAtRisk`). It asks for the existing acknowledgement only when that count is above 0, and names the count. The P1 stopgap warning is removed.

### 7. Recovery code format: 128 bits, Crockford base32, 10-bit checksum
The code has 28 symbols in seven groups of four, which is typeable and readable aloud. It looks nothing like the server-minted account recovery code (12 lowercase symbols in three groups), and the UI calls it the "encryption recovery code". The checksum catches typos locally, about 1023 in 1024 of them, before a rate-limited request is spent. NFKC and the `I`/`L`/`O` folds forgive the usual misreadings.

### 8. KDF: PBKDF2-HMAC-SHA256, 600 000 iterations, random salt
The code is 128 random bits, so offline guessing is infeasible even with a fast KDF. PBKDF2 at the login iteration count is defence in depth, needs no dependency, and has a WebCrypto path plus the existing `fallbackCrypto` path for plain-HTTP LAN installs. Argon2id would need a new dependency for no gain against a 128-bit secret.

### 9. The copy binds user and public key, not the identity row
The AAD is user ID plus identity public key. The device row ID cannot be used: a reset mints it on the server in the same request that stores the copy. Binding the public key is the stronger check anyway. Opening also requires that the decrypted key produces the listed public key.

### 10. Fetching the copy needs a user-action step-up, is audited and is rate-limited
The copy is never in login, step-up or `GET /me/identity` bodies. A cookie alone never yields it. A password session re-proves its password (silently with the cached login secret); an SSO session confirms the exact request with KySignOn. While `password_admin_known` is set, a local session is refused, so an administrator who knows the password cannot fetch it. Each fetch is audited with the copy's ID. The `recovery` bucket (20 an hour by default) bounds fetches and audit rows. The server never sees the code.

### 11. Rotating the code is a compare-and-swap; the old code dies with the old copy
`PUT …/recovery` carries the `recoveryId` the browser last saw. A stale ID (another tab or browser replaced it) is `409 already_exists`. The browser says so and sends nothing else, so the user never holds a code that silently stopped working. The new copy replaces the old one in place, so the old code opens nothing **on the live server**. Database backups and snapshots taken earlier still hold the old copy, and the old code opens it to the current identity. So the replacement copy must not promise that a leaked code is neutralised: after a leak, only the self-service reset cuts the old code off.

### 12. The code is uploaded only after the user proves they kept it
The dialog shows the code, then hides it and asks for one group of four symbols, picked at random when the code was prepared and named only now ("Type group 3 of 7"), from the user's saved copy. Only then does `confirmRecoverySaved` mark the prepared code as uploadable. A replacement kills the previous code, so uploading a code nobody wrote down would silently remove the user's recovery. The prepared code is never stored.

### 13. Administrator resets and account recovery keep the identity (decision D2 resolved)
Before P5, a reset deleted the identity "because without the old password it is unrecoverable". With a recovery code and linked browsers that is no longer true. Deleting it would also destroy every personal notebook, which an administrator should not be able to do. So both paths now remove only the password copy and audit `identity.password_wrap.delete`. The user gets the identity back from another browser or the recovery code once their own password change clears `password_admin_known`. (Needs Yoshi's decision 1.)

### 14. Self-service reset ships now, step-up gated and explicit
Ruling 13 removes the administrator loss path, so the user needs a path for spec §8 item 5 ("lose both and the identity resets"). Settings → "Reset encryption key…":
- asks the user to type `RESET` after a warning that names every loss;
- shows the new recovery code and requires the typed-back check;
- sends one `PUT /me/identity` with `replace:true`, the new public key, its recovery copy and `expectedDeviceId` (the identity the browser saw listed), behind a user-action step-up.

The server swaps identities in one transaction, so the new identity never exists without its copy. The swap is a compare-and-swap: a reset from a stale tab or a second browser cannot destroy an identity (and the code saved for it) that another reset just created. When this browser holds the current key the card says a reset is needed only after a lost or stolen browser (`RESET_HELD`); otherwise saving a code is enough. A lost response is finished only when the server lists the new key. The code was saved before the request, so even a tab closed mid-flight can restore. Team owners re-share through the sweep (a changed key asks for confirmation). Personal notebooks are lost, as §8 item 5 says, and so is any team notebook whose keys only this user held (a team with no other owner or admin holding them), plus edits waiting on this browser under the old identity's waiting key. `RESET_CONFIRM` names all three.

### 15. After a reset the identity is never wrapped under a password again
A reset identity is created with `wrapAlg: none` plus its recovery copy, whatever the session kind. A password-wrapped identity whose copy a reset removed stays device-and-code only. The server never again holds a password-guessable copy of it. New browsers get it by linking or the code. (Needs Yoshi's decision 2.)

### 16. Who is shown the code, and when
SSO accounts see the recovery dialog right after "Set up encryption key" succeeds (§8 item 1: the first browser shows the code). That costs a second KySignOn confirmation (`ponytail:` upgrade: send the copy with the create). Password accounts already have a server copy (their password), so a banner asks them to save a code. Every account without a code sees the banner until it does.

### 17. Restoring never overwrites another key on this browser
`restoreIdentity` refuses (`OTHER_COPY`) when this browser's vault holds a different key, the same rule as `finishNewcomerLink`. It stores compare-and-swap against the copy it read.

### 18. Administrator-created teams are minted and named at creation
The administrator who creates a team is its owner, so its own browser mints the key and seals the name, through the same `createNamed`. `AdminTeams` no longer writes with the login key: the legacy "rename unshared team" path is removed. Names come from the workspace's decrypted names, then from legacy reads of old never-shared teams.

### 19. Phone pairing is deferred again
Spec §7 P5 lists "phone pairing UI", and P3c ruling 18 deferred phone linking, QR codes and the device-recipient sender rule to P5. This brief scopes P5 to personal keys and the recovery code, so those three move to a later phase. The spec records it.

## Needs Yoshi's decision

1. **Administrator password reset and account recovery keep the identity** (ruling 13). Picked: keep it, and remove only the password copy. Cost: an administrator can no longer cut a stolen browser's copy of the identity off from future team keys. The user does that with the self-service reset, which is also the only way an identity is ever destroyed. The alternative keeps P3c's "reset deletes the identity" and makes the recovery code useless in the "forgot my password" case, while letting an administrator destroy a user's personal notebooks.
   Pre-flight: of the two options, keeping is the safer interim, but it is not free. It contradicts the stack's P3c docs and the P3b e2e (an administrator reset deleted the identity, device-only included; Tasks 10 and 11 update them). On a local-only account an administrator can still take the account over (P3c accepted residual), change the password and run the self-service reset, so "an administrator cannot destroy personal notebooks" holds only for accounts with a KySignOn subject. The administrator reset alert therefore tells the administrator to ask the user to reset their key if a browser was lost or stolen.
2. **A reset identity is never password-wrapped again** (ruling 15). Picked: no password copy after a reset. Password users then unlock new browsers by linking or with the code, not with their password. The alternative re-wraps under the next password. That gives the server an offline password-guessing target again, which the user's reset was arguably meant to end.
   Pre-flight: this is the safer interim, and the server already enforces it (`/auth/password` re-wraps only `wrap_alg='aes-256-gcm'`). It narrows the owner-approved spec §8 line "Password users keep the password unwrap path from P1": after any administrator reset, account recovery or self-service reset, that path is gone for good. Yoshi must approve it as a change to §8, not only as a P5 ruling.

## Review Focus (likely failure modes and their pinning tests)

1. **The code is typed the way people type**: lower case, spaces, `O` for `0`, a trailing newline, or full-width digits from a phone keyboard. It must restore. Pinned by `recovery.test.ts` "accepts the code however it is typed" (Task 3).
2. **The upload response is lost after the server stored the copy** (network drop), or another tab rotates the code meanwhile. The user must never be left believing a dead code works. Pinned by `recovery.test.ts` "a stale code ID is reported, not retried" and "a prepared code is sent once" (Task 4), and `TestIdentityRecoveryIsCompareAndSwap` (Task 1).
3. **A reset whose response was lost.** It must finish when the server lists the new key, and fail otherwise. Pinned by `recovery.test.ts` "a reset whose response was lost finishes only for its own key" (Task 4).
4. **Restoring on a browser whose vault holds another key** (an orphan from an old reset). It must refuse rather than overwrite. Pinned by `recovery.test.ts` "never overwrites another key this browser holds" (Task 4).
5. **A password change while a notebook has never been opened since the upgrade.** The form must name the count and require the acknowledgement. Pinned by `passwordChange.test.ts` "asks for an acknowledgement only while a notebook may still hold login-key items" (Task 7).
6. **A notebook created while the mint is refused** (an SSO account without a code, a cancelled KySignOn). It must say why and must not write a name under the login key. Pinned by `legacyWiring.test.ts` "creates every notebook through createNamed and never seals with the login key" (Task 7) and e2e step P5-3 (Task 11).

func writeIdentityError(w http.ResponseWriter, r *http.Request, err error) bool {
	switch {
	case err == nil:
		return false
	case errors.Is(err, auth.ErrSessionInvalid):

func deleteIdentityTx(tx *sql.Tx, userID, actor, requestID string) error {
	if _, err := tx.Exec(`DELETE FROM link_requests WHERE user_id=?`, userID); err != nil {
		return err
	}
	var deviceID string
	err := tx.QueryRow(`DELETE FROM devices WHERE user_id=? AND platform='identity' RETURNING id`, userID).Scan(&deviceID)
	if errors.Is(err, sql.ErrNoRows) {
		return nil
	}
	if err != nil {
		return err
	}
	return storage.RecordAuditOutcomeTx(tx, actor, "identity.reset", "", deviceID, "success", "", requestID)
}

// stripPasswordWrapTx serves account recovery and an administrator password reset: whoever sets the
// new password cannot re-wrap the identity, so only its password copy goes. The identity, its envelopes

	if errors.Is(err, sql.ErrNoRows) {

	}
	if err != nil {
		return err
	}

func recoveryChecksum(secret []byte) uint64 {
	sum := sha256.Sum256(append([]byte(recoveryCodeLabel), secret...))
	return uint64(sum[0])<<2 | uint64(sum[1])>>6
}

// recoveryCode is secret<<10 | checksum as 28 big-endian Crockford symbols, in groups of four.
func recoveryCode(secret []byte) string {
	v := new(big.Int).Lsh(new(big.Int).SetBytes(secret), 10)
	v.Or(v, new(big.Int).SetUint64(recoveryChecksum(secret)))
	out := make([]byte, 28)
	for i := 27; i >= 0; i-- {
		out[i] = crockford[new(big.Int).And(v, big.NewInt(31)).Int64()]
		v.Rsh(v, 5)
	}
	groups := make([]string, 0, 7)
	for i := 0; i < 28; i += 4 {
		groups = append(groups, string(out[i:i+4]))
	}
	return strings.Join(groups, "-")
}

var errRecoveryCode = errors.New("recovery code")

// parseRecoveryCode is the ASCII part of the web parser (the browser adds NFKC first).
func parseRecoveryCode(input string) ([]byte, error) {
	s := strings.NewReplacer(" ", "", "\t", "", "\n", "", "-", "", "I", "1", "L", "1", "O", "0").Replace(strings.ToUpper(input))
	if len(s) != 28 {
		return nil, errRecoveryCode
	}
	v := new(big.Int)
	for _, c := range s {
		d := strings.IndexRune(crockford, c)
		if d < 0 {
			return nil, errRecoveryCode
		}
		v.Lsh(v, 5).Or(v, big.NewInt(int64(d)))
	}
	if v.BitLen() > 138 {
		return nil, errRecoveryCode
	}
	secret := new(big.Int).Rsh(v, 10).FillBytes(make([]byte, 16))
	if recoveryChecksum(secret) != new(big.Int).And(v, big.NewInt(1023)).Uint64() {
		return nil, errRecoveryCode
	}
	return secret, nil
}

func recoveryVectorFor(t *testing.T, secret []byte, userID string, privateKey, salt, nonce []byte) recoveryVector {
	t.Helper()

}

func seq(from byte, n int) []byte {
	out := make([]byte, n)
	for i := range out {
		out[i] = from + byte(i)
	}
	return out
}

func generateRecovery(t *testing.T) recoveryVectors {
	codes := []recoveryVector{
		recoveryVectorFor(t, seq(0, 16), "usr_0123456789abcdefghjkmnpqrs", bytes.Repeat([]byte{0x11}, 32), seq(0x20, 16), seq(0x40, 12)),
		recoveryVectorFor(t, bytes.Repeat([]byte{0xff}, 16), "usr_zyxwvtsrqpnmkjhgfedcba9876", bytes.Repeat([]byte{0x22}, 32), seq(0x60, 16), seq(0x80, 12)),
		recoveryVectorFor(t, make([]byte, 16), "usr_0123456789abcdefghjkmnpqrs", bytes.Repeat([]byte{0x33}, 32), seq(0xa0, 16), seq(0xc0, 12)),
	}
	base := codes[0].Code
	flat := strings.ReplaceAll(base, "-", "")
	aliases := []recoveryInput{
		{Case: "lowercase", Input: strings.ToLower(base)},
		{Case: "spaces", Input: strings.ReplaceAll(base, "-", " ")},
		{Case: "no-separators", Input: flat},
		{Case: "letters-for-digits", Input: strings.NewReplacer("0", "O", "1", "l").Replace(base)},
		{Case: "surrounding-whitespace", Input: "  " + base + "\n"},
	}
	for i := range aliases {
		aliases[i].Code = base
	}
	// The first single-symbol change and the first adjacent swap the checksum catches (deterministic).
	var typo, swap string
	for i := 0; i < 28 && typo == ""; i++ {
		for _, c := range crockford {
			candidate := flat[:i] + string(c) + flat[i+1:]
			if candidate != flat && candidate[0] < '8' {
				if _, err := parseRecoveryCode(candidate); err != nil {
					typo = candidate
					break
				}
			}
		}
	}
	for i := 0; i < 27 && swap == ""; i++ {
		candidate := flat[:i] + string(flat[i+1]) + string(flat[i]) + flat[i+2:]
		if _, err := parseRecoveryCode(candidate); candidate != flat && err != nil {
			swap = candidate
		}
	}
	rejects := []recoveryInput{
		{Case: "short", Input: flat[:27]},
		{Case: "long", Input: flat + "0"},
		{Case: "bad-symbol", Input: flat[:5] + "U" + flat[6:]},
		{Case: "overflow", Input: "Z" + flat[1:]},
		{Case: "typo", Input: typo},
		{Case: "transposed", Input: swap},
	}
	return recoveryVectors{Codes: codes, Aliases: aliases, Rejects: rejects}
}

async function pbkdf2Bits(input: Uint8Array, salt: Uint8Array, iterations: number): Promise<Uint8Array> {
  if (hasNativeSubtle()) {

    }

export const RECOVERY_ALG = "pbkdf2-sha256-600000/aes-256-gcm";
export const RECOVERY_BYTES = 76;
const SECRET_BYTES = 16;
const SYMBOLS = 28;
const ALPHABET = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"; // Crockford base32
const CODE_LABEL = "kynotes/recovery-code/v1";
const WRAP_LABEL = "kynotes/identity-recovery/v1";

export const RECOVERY_TYPO = "Check the recovery code: a character is wrong or missing.";
export const RECOVERY_WRONG = "This recovery code does not open your key. Check it and try again.";
export const RECOVERY_NONE = "Your account has no recovery code. Link this browser from one that holds your key, or reset your encryption key.";

export class RecoveryCodeError extends Error {
  constructor(message = RECOVERY_TYPO) {
    super(message);
    this.name = "RecoveryCodeError";
  }
}

/** First 10 bits of SHA-256(label | secret): a typo is caught here, before any request. */
const checksum = (secret: Uint8Array) => {
  const sum = sha256(concat(encoder.encode(CODE_LABEL), secret));
  return BigInt((sum[0] << 2) | (sum[1] >> 6));
};

/** secret << 10 | checksum as 28 big-endian Crockford symbols in seven groups of four. */
export function formatRecoveryCode(secret: Uint8Array): string {
  if (secret.length !== SECRET_BYTES) throw new Error("invalid recovery secret");
  let value = (secret.reduce((acc, byte) => (acc << 8n) | BigInt(byte), 0n) << 10n) | checksum(secret);
  const symbols: string[] = [];
  for (let i = 0; i < SYMBOLS; i++) {
    symbols.unshift(ALPHABET[Number(value & 31n)]);
    value >>= 5n;
  }
  return symbols.join("").match(/.{4}/g)!.join("-");
}

/** NFKC, any case, spaces and dashes ignored, I/L read as 1 and O as 0. Throws RecoveryCodeError otherwise. */
export function parseRecoveryCode(input: string): Uint8Array {
  const symbols = input.normalize("NFKC").toUpperCase().replace(/[\s-]/g, "").replace(/[IL]/g, "1").replace(/O/g, "0");
  if (symbols.length !== SYMBOLS) throw new RecoveryCodeError();
  let value = 0n;
  for (const symbol of symbols) {
    const digit = ALPHABET.indexOf(symbol);
    if (digit < 0) throw new RecoveryCodeError();
    value = (value << 5n) | BigInt(digit);
  }
  if (value >> 138n) throw new RecoveryCodeError();
  const secret = new Uint8Array(SECRET_BYTES);
  let body = value >> 10n;
  for (let i = SECRET_BYTES - 1; i >= 0; i--) {
    secret[i] = Number(body & 255n);
    body >>= 8n;
  }
  if (checksum(secret) !== (value & 1023n)) throw new RecoveryCodeError();
  return secret;
}

export function newRecoveryCode(): { code: string; secret: Uint8Array } {
  const secret = randomBytes(SECRET_BYTES);
  return { code: formatRecoveryCode(secret), secret };
}

/** AAD binds the account and the exact public key (a reset mints the device ID with the copy, so it cannot be bound). */
const aad = (userID: string, publicKey: Uint8Array) => concat(encoder.encode(WRAP_LABEL), idBytes("usr", userID), publicKey);

/** Test-only: fixed salt and nonce for testdata/protocol/recovery_vectors.json. */
export async function sealRecoveryForVector(secret: Uint8Array, privateKey: Uint8Array, userID: string, salt: Uint8Array, nonce: Uint8Array): Promise<Uint8Array> {
  if (secret.length !== SECRET_BYTES || privateKey.length !== 32 || salt.length !== 16 || nonce.length !== 12) throw new Error("invalid recovery input");
  const kek = await deriveRecoveryKEK(secret, salt);
  return concat(salt, nonce, gcm(kek, nonce, aad(userID, x25519.getPublicKey(privateKey))).encrypt(privateKey));
}

export const sealRecovery = (secret: Uint8Array, identity: Identity, userID: string) =>
  sealRecoveryForVector(secret, identity.privateKey, userID, randomBytes(16), randomBytes(12));

/** Opens the server's copy; anything but this code, user and listed public key is RECOVERY_WRONG. */
export async function openRecovery(secret: Uint8Array, wrapped: Uint8Array, userID: string, listed: { deviceId: string; publicKey: string }): Promise<HeldIdentity> {
  if (wrapped.length !== RECOVERY_BYTES) throw new RecoveryCodeError(RECOVERY_WRONG);
  const publicKey = publicKeyBytes(listed.publicKey);
  const kek = await deriveRecoveryKEK(secret, wrapped.subarray(0, 16));
  let privateKey: Uint8Array;
  try {
    privateKey = gcm(kek, wrapped.subarray(16, 28), aad(userID, publicKey)).decrypt(wrapped.subarray(28));
  } catch {
    throw new RecoveryCodeError(RECOVERY_WRONG);
  }
  if (!sameBytes(x25519.getPublicKey(privateKey), publicKey)) throw new RecoveryCodeError(RECOVERY_WRONG);
  return { deviceId: listed.deviceId, publicKey, privateKey };
}

export async function prepareRecovery(identity: Identity, userID: string): Promise<PreparedRecovery> {

  let byte: number;

export function confirmRecoverySaved(prepared: PreparedRecovery, typed: string): boolean {
  const fold = (value: string) => value.normalize("NFKC").toUpperCase().replace(/[\s-]/g, "").replace(/[IL]/g, "1").replace(/O/g, "0");
  const ok = fold(typed) === prepared.code.split("-")[prepared.check - 1];

  return ok;

/** Sets or replaces the account's copy (compare-and-swap on expectedRecoveryId); returns the new copy's ID. */
export async function saveRecovery(api: Pick<RecoveryAPI, "putRecovery">, prepared: PreparedRecovery, held: HeldIdentity, expectedRecoveryId: string): Promise<string> {
  if (!kept.has(prepared)) throw new Error(CONFIRM_FIRST);
  if (!sameBytes(prepared.identity.publicKey, held.publicKey)) throw new Error("This recovery code was made for another key. Start again.");
  const { recoveryId } = await api.putRecovery({ deviceId: held.deviceId, expectedRecoveryId, wrapAlg: RECOVERY_ALG, wrappedKey: prepared.wrappedKey });
  kept.delete(prepared);
  return recoveryId;
}

/**
 * Gets the identity back on a browser that does not hold it, from the server's copy and the typed code.
 * A typo fails before any request. Never overwrites a different key this browser holds (OTHER_COPY).
 */
export async function restoreIdentity(api: Pick<RecoveryAPI, "fetchRecovery">, store: IdentityStore, userID: string, input: string): Promise<HeldIdentity> {
  const secret = parseRecoveryCode(input);
  const copy = await api.fetchRecovery();
  if (!copy) throw new Error(RECOVERY_NONE);
  if (copy.wrapAlg !== RECOVERY_ALG) throw new Error("This recovery code was saved by a newer version of KyNotes. Update this browser's page and try again.");
  const identity = await openRecovery(secret, fromBase64(copy.wrappedKey), userID, copy);
  const current = await store.load();
  if (current && !sameBytes(current.publicKey, identity.publicKey)) throw new Error(OTHER_COPY);
  if (current?.deviceId === identity.deviceId) return current;
  if (!(await store.save(identity, current ?? null))) throw new LinkStorageError();
  return identity;
}

/**
 * The self-service reset (spec §8 item 5): a new identity and its recovery copy replace the old one in
 * one request. A lost response is finished only when the server lists this new key. The code was saved
 * before the request, so a tab that dies after the commit restores with it.
 * ponytail: personal notebooks are lost even when this browser still holds the old key. Upgrade: an
 * identity rotation that re-wraps held container keys to the new identity before the swap.
 */
/** expectedDeviceId: the identity the browser saw listed ("" for none); the server refuses a reset of any other (409). */
export async function resetIdentity(api: Pick<RecoveryAPI, "replaceIdentity" | "myIdentity">, store: IdentityStore, prepared: PreparedRecovery, expectedDeviceId: string): Promise<{ identity: HeldIdentity; kept: boolean }> {
  if (!kept.has(prepared)) throw new Error(CONFIRM_FIRST);
  let deviceId: string;
  try {
    ({ deviceId } = await api.replaceIdentity({ publicKey: base64(prepared.identity.publicKey), expectedDeviceId, recovery: { wrapAlg: RECOVERY_ALG, wrappedKey: prepared.wrappedKey } }));
  } catch (error) {
    const live = await api.myIdentity().catch(() => undefined);
    if (!live || !sameBytes(publicKeyBytes(live.publicKey), prepared.identity.publicKey)) throw error;
    deviceId = live.deviceId;
  }
  kept.delete(prepared);
  const identity = { ...prepared.identity, deviceId };
  // The reset replaces whatever this browser held: no compare-and-swap.
  return { identity, kept: await store.save(identity) };
}

export type SweepPlan =
  | { kind: "idle" }
  | { kind: "unrecoverable" }
  | { kind: "mint"; recipients: MemberKey[] }
  | { kind: "wrap"; grants: Array<{ member: MemberKey; generation: number }> };

/**
 * What an owner or admin's browser must do so every member holds the container keys.
 * - Never shared: mint the first key for every member with an identity (the others are wrapped by a
 *   later sweep), but only once the caller's own identity is recoverable: a key only a browser holds
 *   would lose the notebook with the browser.
 * - Shared, current generation empty (after a removal): mint the next key.
 * - Otherwise wrap every generation this browser holds for each member missing it.
 * Only keys this browser unwrapped are ever wrapped (P2 rule 7).
 */
export function planSweep(input: { container: KeyedContainer; me: string; members: MemberKey[]; envelopes: Envelope[]; ring: Keyring; recoverable: boolean }): SweepPlan {
  const { container, me, members, envelopes, ring } = input;
  const self = members.find((member) => member.userId === me);
  if (!self?.identity || !isSteward(self.role)) return { kind: "idle" };
  const keyed = members.filter((member) => member.identity);
  if (container.sharedGeneration === 0) return input.recoverable ? { kind: "mint", recipients: keyed } : { kind: "unrecoverable" };
  if (!envelopes.some((row) => row.keyGeneration === container.keyGeneration)) return { kind: "mint", recipients: keyed };
  const held = new Set(envelopes.map((row) => `${row.deviceId}:${row.keyGeneration}`));
  const grants = keyed.flatMap((member) => [...ring.keys()]
    .filter((generation) => generation >= container.sharedGeneration && generation <= container.keyGeneration)
    .filter((generation) => !held.has(`${member.identity!.deviceId}:${generation}`))
    .map((generation) => ({ member, generation })));
  return grants.length ? { kind: "wrap", grants } : { kind: "idle" };
}

/**
 * Spec §8 item 5: lose everything, explicitly. A new key and its recovery code replace the listed key
 * (live.deviceId, compare-and-swap) in one request. held: this browser holds the current key.

export function IdentityReset({ userID, store, live, held, stepUp, onReset }: { userID: string; store: IdentityStore; live: PublicIdentity | undefined; held: boolean; stepUp: () => Promise<void>; onReset: () => void }) {
  const [prepared, setPrepared] = useState<PreparedRecovery>();
  const [hidden, setHidden] = useState(false);
  const [status, setStatus] = useState("");
  async function begin() {
    if (held && !confirm(RESET_HELD)) return;
    if (!resetConfirmed(prompt(RESET_CONFIRM))) return;
    setStatus("");
    setPrepared(await prepareRecovery(generateIdentity(), userID));
    setHidden(false);
  }
  async function finish() {
    try {
      await stepUp();
      const { kept } = await resetIdentity(recoveryAPI, store, prepared!, live?.deviceId ?? "");
      setStatus(kept ? RESET_DONE : RESET_UNKEPT);
      setPrepared(undefined);
      onReset();
    } catch (error) {
      setStatus((error as { code?: string }).code === "already_exists" ? "Your encryption key changed in another tab or browser. Reload and check before resetting again." : linkRefusal(error, "reset your encryption key").message);
      setPrepared(undefined);
    }
  }
  return (
    <section id="identity-reset" className="config-card">
      <h2>Reset encryption key</h2>
      <p className="config-muted">{held ? RESET_HELD : "Only if no browser holds your key and you have no recovery code. Your personal notebooks are lost."}</p>
      {!prepared && <button className="secondary danger" onClick={() => void begin()}>Reset encryption key…</button>}
      {prepared && !hidden && <CodeShown code={prepared.code} onNext={() => setHidden(true)} />}
      {prepared && hidden && <TypeBack prepared={prepared} onBack={() => setHidden(false)} onConfirmed={finish} />}
      {status && <p role="status">{status}</p>}
    </section>
  );
}

/** One API call from page's session, as a KyNotes tab from before P5 made it (CSRF included). */
async function rawSend<T = undefined>(page: Page, path: string, init: { method: string; json?: unknown; bytes?: number[]; headers?: Record<string, string> }): Promise<T> {
  return page.evaluate(async ({ path, init }) => {
    const csrf = document.cookie.split("; ").find((value) => value.startsWith("csrf_token="))?.slice(11) ?? "";
    const headers: Record<string, string> = { "X-CSRF-Token": csrf, ...init.headers };
    if (init.json !== undefined) headers["Content-Type"] = "application/json";
    const body = init.json !== undefined ? JSON.stringify(init.json) : init.bytes ? new Uint8Array(init.bytes) : undefined;
    const response = await fetch(path, { method: init.method, headers, body });
    if (!response.ok) throw new Error(`${path}: ${response.status} ${await response.text()}`);
    return (response.status === 204 ? undefined : await response.json()) as T;
  }, { path, init });
}

/** What a pre-P5 tab wrote: login-key ciphertext at generation 1 (a page, and optionally its comment and attachment). */
async function oldClientWrites(page: Page, cid: string, rows: { title: string; comment?: string; file?: { name: string; text: string } }) {
  const login = legacyKeyRef((await vaultOf(page))!.authSecret);
  const { id } = await rawSend<{ id: string }>(page, `/api/v1/containers/${cid}/objects`, { method: "POST", json: { kind: "note" } });
  const note = await encryptNote(login, cid, { type: "page", title: rows.title, body: "" });
  const saved = await rawSend<{ version: number }>(page, `/api/v1/objects/${id}`, { method: "PUT", bytes: [...note], headers: { "Content-Type": "application/octet-stream", "X-Kynotes-Base-Version": "0", "X-Kynotes-Key-Generation": "1" } });
  if (rows.comment) await rawSend(page, `/api/v1/objects/${id}/comments`, { method: "POST", json: { bodyCiphertext: base64(await encryptComment(login, cid, rows.comment)), keyGeneration: 1, mentions: [] } });
  if (rows.file) {
    const bytes = await encryptAttachment(login, cid, new TextEncoder().encode(rows.file.text));
    const upload = await rawSend<{ uploadId: string }>(page, `/api/v1/containers/${cid}/uploads`, { method: "POST", json: { declaredBytes: bytes.length, expectedDigest: createHash("sha256").update(bytes).digest("hex"), kind: "attachment" } });
    await rawSend(page, `/api/v1/uploads/${upload.uploadId}`, { method: "PATCH", bytes: [...bytes], headers: { "Content-Type": "application/octet-stream", "X-Kynotes-Chunk-Index": "0" } });
    const metadata = base64(await encryptAttachmentMetadata(login, cid, { name: rows.file.name, type: "text/plain", size: rows.file.text.length }));
    const done = await rawSend<{ attachmentId: string }>(page, `/api/v1/uploads/${upload.uploadId}/finalize`, { method: "POST", json: { metadataCiphertext: metadata, keyGeneration: 1 } });
    await rawSend(page, `/api/v1/objects/${id}/attachments`, { method: "POST", json: { attachmentId: done.attachmentId, objectVersion: saved.version } });
  }
  return id;
}
