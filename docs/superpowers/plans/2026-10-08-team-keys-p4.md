# Team Keys Phase 4 (Legacy Migration and Closure) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A member re-seals the pre-sharing rows of a shared notebook that only their own login-derived key opens, after reviewing them, and each browser then stops opening any server row of that notebook with the login key. This closes the P3a "server-forged pre-sharing rows" residual.

**Architecture:** The closure is a per-device, per-notebook flag (`KeyFloor.closed`). It sits beside the existing add-only sharing floor, which is persisted in the vault's key memory and broadcast to other tabs. Once the flag is set, `readKeys` never returns the login key for a server row in that notebook. Entries this browser wrote to IndexedDB itself (the queue, the cache and pending uploads) still open through `localReadKeys`. The server gains one read-only route, `GET /api/v1/containers/{id}/legacy`. It lists rows below `shared_generation` and is only a hint. A pure `migration.ts` does the rest:
- `reviewLegacy` opens each listed row with the login key only, using the same `readKeys` decision that labels it.
- `migrateLegacy` re-seals only rows that carry a `MigrationApproval`, which only the review dialog mints. It works through the existing outbound gate and conflict machinery, then closes the notebook if nothing failed.

A browser closes a notebook by itself when the server lists nothing its key opens. "Stop opening pre-sharing items" closes it without any server cooperation.

**Tech Stack:** Go 1.26 (`net/http`, SQLite via `modernc`), TypeScript/React (Vite, vitest, fake-indexeddb), `@playwright/test` 1.63.0 (already a devDependency). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-07-team-keys-design.md`. The relevant sections:

Conventions follow `docs/superpowers/plans/2026-10-08-team-keys-p3c.md`.

## Resolved ambiguities (recorded in the spec in Task 9)

### 1. Closure is per device and per notebook, because a legacy read only ever serves its reader
The login-derived key is `HKDF(authSecret_reader, salt = containerID)`. A row below `sharedGeneration` therefore opens only for its own author, and for the server, which sees `authSecret` (F1). From reader R's point of view, every legacy row R can open is either R's own pre-sharing content or a forgery. Rows by other authors never open for R. Closure is therefore a statement about R's own rows, and R's device is the right place to decide it.

Container-wide closure was considered: a steward-written "legacy closed at generation N" marker, sealed under the CK and stored on the server. A malicious server can withhold that marker from any device, so against the attacker in question it gives nothing that per-device closure does not. It also needs new server state and a route, and it cuts unmigrated authors off from their own content. (Needs Yoshi's decision 1.)

### 2. The server's list is a hint. No migration `0025`, one read-only route
`GET /containers/{id}/legacy` makes the review one request, not three per page. It also feeds the opaque-row count. Trusting it costs nothing on security:
- A row the server adds is opened with the reader's own key and shown for review. It is never re-sealed without approval.
- A row the server omits is, after closure, unreadable to its author. That is denial of service on content the server could delete anyway.
- Withholding the route only stops auto-close. The user can still close by hand (ruling 6).

The server cannot tell a migrated row from a forged one, so server-side enforcement would prove nothing. A `legacy_closed_generation` column was rejected for the same reason.

### 3. Migration is an explicit review, never a background pass
Spec §4 proposed a background re-encryption pass on open. That pass would turn any forgery planted before it ran into a row sealed under the CK, which no one could ever tell from verified content again. Migration on edit only (today's rule) would never finish, so closure would never come.

The review satisfies the existing rule "never re-seal a labelled row without an explicit user action": the user sees every row their key opens, labelled, and ticks the ones they recognise. Only ticked rows are re-sealed. The explicit edit or move path from P3a stays.

### 4. Items start unticked
"Select all" is one click. Ticking is the user vouching for content that the server could have forged, so the default is "no".

### 5. Auto-close when nothing of yours is listed
A browser closes a notebook without asking once the server's list is complete and none of the listed rows opens with this user's key. This covers:
- new members;
- the owner who minted;
- every other browser of an author who already migrated.

Closing can only fail closed. A forged row is the only way to keep a device open, and it shows up labelled, in the review. (Needs Yoshi's decision 2.)

### 6. Closing by hand needs no server cooperation
"Stop opening pre-sharing items" is offered whenever the device is still open, including when the list failed or is incomplete. The server can therefore delay closure only by forcing a click, and it can never prevent it. This meets "(b) cannot block closure forever without being visible".

### 7. Local entries are outside the closure
Queued saves, pending uploads and cached copies are written by this browser to IndexedDB, and the server cannot write them. Closing must not strand an edit queued before sharing, or one waiting at generation 0, so `localReadKeys` ignores `closed`. Every server row keeps going through `readKeys`.

### 8. A comment that opens with your key but names another author is refused
Before sharing, only the author's key sealed a comment. A comment that opens with R's key but is labelled with another author is therefore forged, either in its content or in its author field. It is counted as `refused`, never offered for sharing, and does not block auto-close. Closing hides it.

### 9. Attachments are replaced, and pages pointing at them are rewritten first
An attachment is re-sealed as a new attachment through the existing upload path, so it is resumable and goes through outbound. The new attachment is attached to every page that referenced the old one. Each such page is re-saved with `attachment://old` replaced by `attachment://new`. Only after a page's re-save succeeds is the old attachment detached from that page. A page that fails keeps the old attachment, and the notebook stays open.

Previews are never written by the web client, so there is nothing to migrate. A replaced attachment's preview goes with its detached row.

### 10. Conflicting versions become copies only when ticked
A legacy conflict record that the user's key opens is listed. If ticked, it is kept as a copy next to its page with the existing placement code (`placeConflictCopy`, extracted from `keepConflictCopies`) and then resolved. Unticked records stay unresolved on the server.

### 11. Container meta needs no migration; the admin page stops reading shared names with the login key
A notebook name has no row generation and is always read at the current generation, so a shared container's name opens only with the CK (P3a). The first mint re-seals the pre-sharing name (`resealName`). `resealName`'s comparison list now uses `legacyKeys`, so a closed device never tries the login key. `AdminTeams` decrypted every team name with the login key. It now goes through `readKeys`, so a shared team's name is never read there with a key the server can derive.

### 12. Rows of removed or departed authors stay opaque
No current member can open them. They are counted ("N items written before this notebook was shared can be opened only by their authors") and never deleted automatically. A re-admitted author whose device has not closed can still review them. Deleting them needs a UI that does not exist (known limit).

### 13. Authors who cannot write keep their rows until they close
A viewer, or a demoted author, cannot re-save. The server refuses (`403`), the review reports which items failed, and nothing closes. "Stop opening pre-sharing items" still works for them.

### 14. Version conflicts use the existing machinery
A re-seal is a normal save with `baseVersion` = the version reviewed. If the page changed meanwhile (another tab of the same author), the server stores a conflict record. The item is reported as failed and the notebook stays open. The next review no longer lists the row if it is now at a shared generation.

### 15. `author_user_id` stays write-only
The review needs object authors only for display. The comment author is already in the list and is enough for ruling 8. P2 ruling 12's note changes from "until P4" to "(not needed by P4)".

### 16. Administrator-owned teams wait for sub-project A
The administrator who created a team is its owner today and, for P4, an ordinary author. Hand-over to a named owner belongs to sub-project A.

## Needs Yoshi's decision

1. **Per-device closure instead of a container-wide steward marker.** The alternative closes legacy reads for every member when a steward decides. The cost is that members who have not reviewed lose their own pre-sharing content, and the server could withhold the marker anyway. Its only gain is against a server that turns malicious *after* a device has fetched the marker. Picked: per device (ruling 1). A member who never reviews keeps seeing labelled rows, as in P3a.
2. **Auto-close trusts the server's list for completeness.** A lying or broken server can make a device close before its author reviewed, which hides that author's unreviewed rows on that device. That is denial of service only, on content the server could delete. The only way back is "Forget this device", which also drops pins and key memory. The alternative is closing only by hand, per notebook and per browser, and nobody would ever do it. Picked: auto-close (ruling 5). There is no "reopen" button, because a button that reopens is a downgrade path.

## Review Focus (likely failure modes and their pinning tests)

1. **A notebook with more than 1000 legacy rows of one kind.** The list is incomplete. A reasonable person expects no silent closure, a clear "could not check everything" banner, and closing by hand still available. Pinned by `TestLegacyRowsReportAnIncompleteList` (Task 1) and `migration.test.ts` "never closes by itself on an incomplete list" (Task 5).
2. **An edit queued before sharing, or waiting at generation 0, when the device closes.** It must still be re-sealed and sent, never stranded. Pinned by `drain.test.ts` "re-seals this browser's own legacy and waiting edits after the closure" (Task 3).
3. **An inline image in a migrated page.** It must still render: the body must point at the new attachment before the old one is detached. Pinned by `migration.test.ts` "rewrites inline references and detaches the old copy only from pages that point at the new one" (Task 6).
4. **The tab closes halfway through a migration.** Re-running must share only what is left, never resend a re-sealed row, and never close early. Pinned by `migration.test.ts` "a second run shares only what the first left, and running it again changes nothing" (Task 6).
5. **The same author edits the page in another tab during the migration.** The version conflict must keep the notebook open and leave the conflict visible. Pinned by `migration.test.ts` "a refused or conflicting write keeps legacy reads open" (Task 6).

```go
// legacyListMax bounds each kind of row GET /containers/{id}/legacy returns; a longer list is
// reported with complete=false, and the web client then never stops reading legacy rows on its own.
const legacyListMax = 1000

// legacyRows reads up to legacyListMax rows of one kind; complete is false when there were more.
func legacyRows(db *sql.DB, query, cid string, shared int64, scan func(*sql.Rows) (map[string]any, error)) ([]map[string]any, bool, error) {
	rows, err := db.Query(query, cid, shared, legacyListMax+1)
	if err != nil {
		return nil, false, err
	}
	defer rows.Close()
	out := []map[string]any{}
	for rows.Next() {
		row, err := scan(rows)
		if err != nil {
			return nil, false, err
		}
		out = append(out, row)
	}
	if err := rows.Err(); err != nil {
		return nil, false, err
	}
	if len(out) > legacyListMax {
		return out[:legacyListMax], false, nil
	}
	return out, true, nil
}
```

```ts
/**
 * The login-derived key for a legacy row, or none once this device closed legacy reads for the
 * container: the server can derive that key, so after the closure no server row opens with it.
 */
export const legacyKeys = (floor: KeyFloor, legacy: KeyRef): KeyRef[] => ((floor.closed ?? 0) > 0 ? [] : [legacy]);

/**
 * The one key a server row may be read with. Rows at or above sharedGeneration open only with
 * their own generation's CK, so neither a relabelled legacy row nor a removed member's older CK
 * can stand in for a newer generation. Older rows, and never-shared containers, use the login key
 * until this device closes legacy reads (legacyKeys). Callers label such rows (legacyRow) and
 * re-seal them only on an explicit edit, move or review (migration.ts).
 */
export function readKeys(container: Pick<KeyedContainer, "sharedGeneration">, ring: Keyring, legacy: KeyRef, generation: number | undefined, floor: KeyFloor): KeyRef[] {
  // A never-shared container has only the legacy key, so a row without a generation (old cache) still reads.
  if (sharedFloor(container, floor) === 0) return legacyKeys(floor, legacy);
  // The same decision labels the row, so a row read with the legacy key is always labelled.
  if (legacyRow(container, generation, floor)) return legacyKeys(floor, legacy);
  if (generation === undefined || !Number.isInteger(generation)) return [];
  const key = ring.get(generation);
  return key ? [key] : [];
```

```ts
import type { LegacyRows } from "./api";
import { decryptAttachmentMetadata, decryptComment, decryptObject, fromBase64, type KeyRef } from "./crypto";
import type { AttachmentFile } from "./drain";
import { legacyKeys, openFirst, readKeys, type KeyFloor, type ReportedContainer } from "./keyring";
import type { ObjectPayload, PagePayload } from "./pages";

/** A row written before this notebook was shared that this user's login key opens: theirs, or a server forgery. */
export type MigrationItem =
  | { kind: "object"; id: string; version: number; payload: ObjectPayload }
  | { kind: "comment"; id: string; objectId: string; comment: { body: string; section?: string } }
  | { kind: "attachment"; id: string; objectIds: string[]; generation: number; file: AttachmentFile }
  | { kind: "conflict"; id: string; objectId: string; payload: PagePayload };
/**
 * mine: rows this user's login key opens, to review; others: listed rows it does not open (another
 * author's, or unreadable); refused: comments that open with this key but name another author, which
 * only a forgery does; complete: the server listed everything and every listed row could be fetched.
 */
export type LegacyReview = { mine: MigrationItem[]; others: number; refused: number; complete: boolean };
export type ReviewAPI = {
  legacyRows: (containerID: string) => Promise<LegacyRows>;
  readObject: (objectID: string) => Promise<{ bytes: Uint8Array; version: number; keyGeneration?: number }>;
  conflictBytes: (conflictID: string) => Promise<Uint8Array>;
};
/** floor: this tab's floor for the container (floors.ts), never the server's sharing state alone. */
export type ReviewInput = { container: ReportedContainer; floor: KeyFloor; legacy: KeyRef; userId: string };

/**
 * The pre-sharing rows of a shared notebook as this user can see them. Each row is opened with the
 * key readKeys picks for its generation and nothing else: the login key for a row below sharing
 * (until this device closes), none otherwise. The server's list only says where to look.
 */
export async function reviewLegacy(api: ReviewAPI, input: ReviewInput): Promise<LegacyReview> {
  const { container, floor, legacy, userId } = input;
  const review: LegacyReview = { mine: [], others: 0, refused: 0, complete: true };
  if (Math.max(container.sharedGeneration, floor.shared ?? 0) === 0) return review;
  const rows = await api.legacyRows(container.id);
  review.complete = rows.complete;
  // Closed on this device: nothing opens with the login key, so every listed row is someone else's to share.
  if (!legacyKeys(floor, legacy).length) return { ...review, others: rows.objects.length + rows.comments.length + rows.attachments.length + rows.conflicts.length };
  const opened = <T>(generation: number | undefined, open: (key: KeyRef) => Promise<T>) =>
    openFirst(readKeys(container, new Map(), legacy, generation, floor), open).catch(() => undefined);

  for (const row of rows.objects) {
    // The current version, re-read: the listed one may have been re-sealed meanwhile.
    const current = await api.readObject(row.id).catch(() => undefined);
    if (!current) { review.complete = false; continue; }
    const payload = await opened(current.keyGeneration, (key) => decryptObject(key, container.id, current.bytes));
    if (payload) review.mine.push({ kind: "object", id: row.id, version: current.version, payload });
    else if (current.keyGeneration !== undefined && current.keyGeneration < Math.max(container.sharedGeneration, floor.shared ?? 0)) review.others += 1;
  }
  for (const row of rows.comments) {
    const comment = await opened(row.keyGeneration, (key) => decryptComment(key, container.id, fromBase64(row.bodyCiphertext)));
    if (!comment) review.others += 1;
    // Before sharing only its author's key sealed a comment: another author's name on one this key opens is forged.
    else if (row.authorUserId !== userId) review.refused += 1;
    else review.mine.push({ kind: "comment", id: row.id, objectId: row.objectId, comment });
  }
  for (const row of rows.attachments) {
    const file = await opened(row.keyGeneration, (key) => decryptAttachmentMetadata(key, container.id, fromBase64(row.metadataCiphertext)));
    if (file && row.keyGeneration !== undefined && row.objectIds.length) review.mine.push({ kind: "attachment", id: row.id, objectIds: row.objectIds, generation: row.keyGeneration, file });
    else review.others += 1;
  }
  for (const row of rows.conflicts) {
    const bytes = await api.conflictBytes(row.id).catch(() => undefined);
    if (!bytes) { review.complete = false; continue; }
    const payload = await opened(row.keyGeneration, (key) => decryptObject(key, container.id, bytes));
    if (payload?.type === "page") review.mine.push({ kind: "conflict", id: row.id, objectId: row.objectId, payload });
    else review.others += 1;
  }
  return review;
}

/** This device may stop opening legacy rows by itself: the whole list was checked and nothing in it is this user's. */
export const autoCloses = (review: LegacyReview): boolean => review.complete && review.mine.length === 0;

/** What the review dialog shows for an item. */
export function itemLabel(item: MigrationItem): string {
  switch (item.kind) {
    case "object": return `${item.payload.type === "page" ? "Page" : item.payload.type === "section" ? "Section" : "Section group"}: ${item.payload.title || "Untitled"}`;
    case "comment": return `Comment: ${item.comment.body.slice(0, 80)}`;
    case "attachment": return `Attachment: ${item.file.name} (${Math.max(1, Math.ceil(item.file.size / 1024))} KB)`;
    case "conflict": return `Conflicting version: ${item.payload.title || "Untitled"}`;
  }
}
```

```ts
    }),
    readObject: async (oid) => ({ ...objects.get(oid)! }),
    conflictBytes: async (fid) => conflicts.get(fid)!.bytes,
    sendObject: async (sealed, oid, bytes, base) => {
      sends.push(`object:${oid}`);
      const row = objects.get(oid)!;
      if (failing.has(oid) || row.version !== base) throw Object.assign(new Error("version_conflict"), { code: "version_conflict" });
      objects.set(oid, { bytes, version: base + 1, keyGeneration: sealed.generation });
      return { version: base + 1 };
    },
    sendCommentRewrite: async (sealed, cid, body) => { sends.push(`comment:${cid}`); comments.set(cid, { ...comments.get(cid)!, body, keyGeneration: sealed.generation }); },
    downloadAttachment: async (aid) => attachments.get(aid)!.bytes,
    uploadAttachment: async (oid, _version, plaintext, file) => {
      const aid = id("att", fresh.shift()!);
      sends.push(`upload:${aid}`);
      attachments.set(aid, { objectIds: [oid], bytes: await encryptAttachment(ck, cnt, plaintext), meta: base64(await encryptAttachmentMetadata(ck, cnt, file)), keyGeneration: 2 });
      return aid;
    },
    attach: async (oid, aid) => { attachments.get(aid)!.objectIds.push(oid); },
    detach: async (oid, aid) => { sends.push(`detach:${aid}:${oid}`); const row = attachments.get(aid)!; row.objectIds = row.objectIds.filter((entry) => entry !== oid); },
    keepConflict: async (_oid, fid) => { sends.push(`conflict:${fid}`); conflicts.delete(fid); return true; },
  };
  const state = () => JSON.stringify({ objects: [...objects].map(([k, v]) => [k, v.version, v.keyGeneration, [...v.bytes]]), comments: [...comments], attachments: [...attachments].map(([k, v]) => [k, v.objectIds, v.keyGeneration]), conflicts: [...conflicts.keys()] });
  return { api, objects, comments, attachments, conflicts, sends, failing, state };
}
```

```ts
/** The rows of one notebook the user ticked in the review dialog; only approveMigration makes one. */
export class MigrationApproval {
  private declare readonly brand: true; // nominal: look-alike objects do not type-check
  static {

      Object.freeze(approval);
      approvals.add(approval);
      return approval;

export const approveMigration = (containerID: string, ids: Iterable<string>): MigrationApproval => mint(containerID, [...ids]);
export const isMigrationApproval = (value: unknown, containerID: string): value is MigrationApproval =>
  typeof value === "object" && value !== null && approvals.has(value as MigrationApproval) && (value as MigrationApproval).containerID === containerID;

const ATTACHMENT_ID = /^att_[0-9a-hjkmnp-tv-z]{26}$/;
/** payload with every attachment://old pointing at renamed[old]; the same object when nothing changed. IDs are fixed-length, so no ID is a prefix of another. */
export function rewriteRefs<T extends ObjectPayload>(payload: T, renamed: Readonly<Record<string, string>>): T {
  const text = JSON.stringify(payload);
  let next = text;
  for (const [old, replacement] of Object.entries(renamed))
    if (ATTACHMENT_ID.test(old) && ATTACHMENT_ID.test(replacement)) next = next.split(`attachment://${old}`).join(`attachment://${replacement}`);
  return next === text ? payload : (JSON.parse(next) as T);
}

export type MigrationAPI = {
  readObject: ReviewAPI["readObject"];
  /** outbound.ts sendObject. */
  sendObject: (sealed: Sealed, objectID: string, bytes: Uint8Array, baseVersion: number) => Promise<{ version: number }>;
  /** outbound.ts sendCommentRewrite. */
  sendCommentRewrite: (sealed: Sealed, commentID: string, bodyCiphertext: string) => Promise<void>;
  downloadAttachment: (attachmentID: string) => Promise<Uint8Array>;
  /** Seals plaintext for the current key, uploads it through outbound.ts and attaches it to objectID; the new attachment ID. */
  uploadAttachment: (objectID: string, objectVersion: number, plaintext: Uint8Array, file: AttachmentFile) => Promise<string>;
  attach: (objectID: string, attachmentID: string, objectVersion: number) => Promise<void>;
  detach: (objectID: string, attachmentID: string) => Promise<void>;
  /** Keeps a rejected page version as a copy next to its page and resolves the record; false when it could not. */
  keepConflict: (objectID: string, conflictID: string, payload: PagePayload) => Promise<boolean>;
};
/** items: the review's mine; ring: this tab's keys for the container (pages that only point at a replaced attachment). */
export type MigrationInput = ReviewInput & { write: WriteKey; ring: Keyring; approval: MigrationApproval; items: MigrationItem[] };
/** shared: approved rows now sealed with the container key; failed: approved rows (or pages pointing at them) that were not; closed: close() ran and kept. */
export type Migrated = { shared: string[]; failed: Array<{ id: string; reason: string }>; closed: boolean };

/**
 * Re-seals the approved pre-sharing rows under the current container key, through the injected
 * outbound sends, and only then, when nothing failed, calls close (closeLegacy). Order matters:
 * attachments get a new copy first; every page pointing at an old copy is re-saved to point at the
 * new one; the old copy leaves a page only after that page's re-save. Re-running it is safe: a
 * re-sealed row is no longer listed, so the next review does not offer it.
 * ponytail: a run that dies between attaching a new copy and detaching the old one leaves the old
 * copy listed, and the next run uploads it again (a duplicate attachment, never lost content).
 * Upgrade: record the source attachment ID in the new copy's metadata and skip it on the next run.
 */
export async function migrateLegacy(api: MigrationAPI, input: MigrationInput, close: () => Promise<boolean>): Promise<Migrated> {
  const { container, floor, legacy, write, ring, approval } = input;
  if (!isMigrationApproval(approval, container.id)) throw new Error("Choose the items to share in the review first.");
  const sealed: Sealed = { container, generation: write.generation };
  const items = input.items.filter((item) => approval.ids.includes(item.id));
  const shared: string[] = [];
  const failed: Migrated["failed"] = [];
  const attempt = async (id: string, run: () => Promise<unknown>, counts = true) => {
    try { await run(); if (counts) shared.push(id); return true; }
    catch (error) { failed.push({ id, reason: error instanceof Error ? error.message : "failed" }); return false; }
  };
  const legacyKey = (generation: number | undefined) => readKeys(container, ring, legacy, generation, floor);

  // 1. Attachments: a new copy under the container key, attached beside the old one on every page.
  const renamed: Record<string, string> = {};
  const replaced: Array<{ old: string; objectIds: string[] }> = [];
  for (const item of items) {
    if (item.kind !== "attachment") continue;
    await attempt(item.id, async () => {
      const bytes = await api.downloadAttachment(item.id);
      const plaintext = await openFirst(legacyKey(item.generation), (key) => decryptAttachment(key, container.id, bytes));
      const versions = await Promise.all(item.objectIds.map(async (objectID) => (await api.readObject(objectID)).version));
      const next = await api.uploadAttachment(item.objectIds[0], versions[0], plaintext, item.file);
      for (let i = 1; i < item.objectIds.length; i += 1) await api.attach(item.objectIds[i], next, versions[i]);
      renamed[item.id] = next;
      replaced.push({ old: item.id, objectIds: item.objectIds });
    });
  }

  // 2. Pages, sections and groups: approved rows, and every page that points at a replaced attachment.
  const approvedObjects = new Map(items.flatMap((item) => (item.kind === "object" ? [[item.id, item] as const] : [])));
  const pointing = new Set(replaced.flatMap((entry) => entry.objectIds));
  const notRewritten = new Set<string>();
  for (const objectID of new Set([...approvedObjects.keys(), ...pointing])) {
    const approved = approvedObjects.get(objectID);
    const ok = await attempt(objectID, async () => {
      let version: number;
      let payload: ObjectPayload | undefined;
      if (approved) ({ version, payload } = approved);
      else {
        // Not ticked: only a row this browser already reads with a container key may be rewritten.
        const current = await api.readObject(objectID);
        if (legacyRow(container, current.keyGeneration, floor)) throw new Error("written before sharing and not ticked");
        payload = await openFirst(legacyKey(current.keyGeneration), (key) => decryptObject(key, container.id, current.bytes));
        version = current.version;
      }
      if (!payload) throw new Error("could not be opened");
      const next = rewriteRefs(payload, renamed);
      if (!approved && next === payload) return;
      await api.sendObject(sealed, objectID, await encryptNote(write.key, container.id, next), version);
    }, Boolean(approved));
    if (!ok) notRewritten.add(objectID);
  }

  // 3. The old copy leaves each page that now points at the new one.
  for (const entry of replaced)
    for (const objectID of entry.objectIds)
      if (!notRewritten.has(objectID)) await attempt(`${entry.old}:${objectID}`, () => api.detach(objectID, entry.old), false);

  // 4. Comments, by their author (the server refuses anyone else).
  for (const item of items) {
    if (item.kind !== "comment") continue;
    await attempt(item.id, async () => api.sendCommentRewrite(sealed, item.id, base64(await encryptComment(write.key, container.id, item.comment.body, item.comment.section ?? ""))));
  }
  // 5. Conflicting versions become copies next to their page.
  for (const item of items) {
    if (item.kind !== "conflict") continue;
    await attempt(item.id, async () => { if (!(await api.keepConflict(item.objectId, item.id, item.payload))) throw new Error("could not be placed next to its page"); });
  }
  // Closing hides every unticked row on this device, so only after everything ticked was shared.
  const closed = failed.length === 0 && (await close().catch(() => false));
  return { shared, failed, closed };
}
```
